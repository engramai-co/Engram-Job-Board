# Candidate decision profile

Use this as a private working template, not as public sample data. Reuse known answers; leave unknowns explicit. The user's latest instructions override earlier preferences. Store sensitive values only in the user-authorized private location.

| Dimension | Capture |
| --- | --- |
| Decision | General search, specific opportunity review, or exceptional alternatives to a satisfactory baseline? |
| Candidate evidence | Authorized CV/version; demonstrated skills, projects, degrees, expected graduation, relevant experience. |
| Timing | Full-time/internship preference, start window, graduation-year constraints. |
| Target work | Desired deliverables and collaborators, not only job titles. |
| Mandate requirements | For example core model work, desk alignment, product engineering, infrastructure; required versus preferred. |
| Exclusions | Explicit employers, mandates, industries, or other user-chosen restrictions. Do not infer universal exclusions. |
| Geography | Ordered primary locations; whether secondary geographies are allowed; work authorization and relocation constraints. |
| Baseline | Current option's role/content, satisfaction, location, currency, base, bonus certainty, sign-on, equity vesting, first-year and recurring compensation. |
| Upgrade threshold | The user's required compensation improvement, career-track change, research proximity, or other tradeoff. |
| Capacity | Maximum active targets; willingness to apply to multiple roles at one employer. |
| Evidence access | Which supplied documents, private records, or connected services are in scope. |
| Deliverable | Advice/table only, private research notes, or explicit board update; no external mutation implied by research alone. |

## Mandate checks

Translate user preferences into observable JD evidence before evaluating employers. These are examples, not defaults:

- **Core AI:** Ownership of model behavior, learning, evaluation, or AI-product capabilities. Ask what fraction of work is model/research versus shared infrastructure when ambiguous.
- **Front-office engineering:** Named desk/strategy alignment plus direct influence on research-to-trading outputs. Ask who sets priorities, who owns the resulting strategies, and whether the team is central or embedded.
- **Research trajectory:** Actual experimentation, publications or research output, access to mentorship, and freedom to drive investigations; a research-sounding title alone is insufficient.

Unknown constraints should not become invented facts. If missing information prevents a defensible recommendation, keep the candidate provisional and ask the smallest decision-changing question.
